Скилл в Claude устроен просто: это папка с файлом SKILL.md, внутри которого инструкция. Claude (по-русски его называют Клодом) открывает ее сам, когда ваша задача совпала с описанием скилла. Пока не совпала, модель видит от скилла только имя и пару строк. В английском интерфейсе функция называется Claude Skills, в русской справке Anthropic «Навыки».

Я редактор, и для меня скилл прежде всего редакционный документ, только читает его модель. Тот же регламент или чек-лист, оформленный так, чтобы Claude находил его сам. Разбираю на двух собственных скиллах: один ходит в Вордстат за частотностью, второй собирает еженедельный отчет по этому сайту. Отдельно покажу, как устроен skill-creator, встроенный помощник Anthropic для написания скиллов. К концу будет понятно, как поставить готовый скилл и написать свой, не будучи программистом.

Пути, настройки и ограничения в статье сверены с документацией Anthropic и актуальны на октябрь 2026 года: Anthropic быстро меняет интерфейс, так что названия пунктов меню со временем могут разойтись.

## Что такое скилл в Claude и почему его не нужно вызывать по имени

Свой скилл для Вордстата я никогда не вызываю по имени. Пишу или наговариваю голосом: подключись к Вордстату, посмотри частотность. Claude сам находит нужный файл и работает по нему. Каждый раз ощущение такое, как будто скиллы вообще не нужно вызывать.

За этим стоит механика, которую в документации Anthropic называют progressive disclosure. По-русски точнее всего подгрузка по необходимости. Скилл попадает в работу модели на трех уровнях:

1. Имя и описание каждого установленного скилла лежат в контексте всегда. Это около 100 токенов на скилл.
2. Основной текст SKILL.md подгружается, только когда задача совпала с описанием. Документация советует укладывать его в 5 тысяч токенов.
3. Остальные файлы папки открываются, только если понадобились. Если в папке есть скрипт, он выполняется, и в контекст попадает только результат его работы.

Контекст это весь текст, который модель держит в голове в рамках одного разговора: ваши сообщения, ее ответы, загруженные файлы, инструкции. У него есть предел, и лишнее в нем мешает: чем больше постороннего, тем проще модели упустить важное. Токен это единица, которой меряют объем контекста. 100 токенов примерно равны паре строк текста.

Поэтому скиллов можно держать десятки: пока они не нужны, они почти ничего не стоят. Инструкция проекта устроена иначе: она лежит в контексте целиком в каждом разговоре. Подробнее про эту разницу ниже, в разделе про CLAUDE.md и соседние инструменты.

В моем случае с Вордстатом смысл запроса совпал с описанием скилла. Буквально слова совпадать не обязаны: я пишу «Вордстату» кириллицей, в описании стоит Wordstat латиницей, и скилл все равно срабатывает. Решение открыть файл модель принимает по описанию. Поэтому описанию в статье отдан отдельный раздел.

## Как устроен SKILL.md: разбор моего скилла для Вордстата

Скилл это папка. У моего скилла для Вордстата она минимальная:

```
wordstat/
└── SKILL.md
```

По стандарту в папке может лежать больше:

```
имя-скилла/
├── SKILL.md       инструкция, единственный обязательный файл
├── scripts/       код, который скилл может запустить
├── references/    справка, которую модель читает по ссылке из SKILL.md
└── assets/        шаблоны и данные
```

У wordstat дополнительных файлов нет: 93 строки текста, и вся логика живет в инструкции. Запрос к API Вордстата Claude отправляет сам, по образцу из файла. API это программный вход в сервис: через него данные получают без браузера.

Файл начинается с шапки. Это несколько строк между двумя строками из трех дефисов, в документации такой блок называют YAML-фронтматтером. В шапке имя и описание, и пока скилл не открыт, это все, что Claude о нем знает. Вот шапка wordstat целиком, как она лежит в файле:

```
---
name: wordstat
description: Использовать при любом запросе на частотность ключевых слов, поисковый интент или семантически близкие запросы через Яндекс Wordstat — для любого продукта или темы, не только для лендингов. Триггерится, когда пользователь просит проверить/собрать ключи, частотность, семантику через Wordstat.
---
```

Описание разберу ниже, в разделе про заголовки. Сначала тело. После шапки идет обычный текст с заголовками разделов, у wordstat их шесть:

```
## Перед использованием
## Основной запрос — топ похожих формулировок + ассоциации
## Дополнительно — распределение по регионам
## Сценарии использования
## Обработка ошибок
## Важно
```

Если убрать технические детали, так устроена любая редполитика: что нужно до начала работы, основной порядок действий, частные случаи, исключения, запреты.

В сценариях скилл различает две ситуации. Если на вход пришел целый бриф по продукту, Claude проходит полный цикл без уточняющих вопросов. Второй сценарий цитирую дословно:

> **Если на вход дана одна конкретная фраза без брифа** («проверь частотность „X“») — просто вызвать `topRequests` по этой фразе и показать результат, без домысливания категорий.

Ровно то, что редактор пишет в регламенте для нового автора: на короткий вопрос отвечай коротко и не разворачивай его в отчет на три страницы.

Дальше предупреждение, фрагмент сокращен:

> **Важно про качество associations:** по опыту реальных вызовов, этот массив может содержать нерелевантный шум (обрывки фраз, случайные сайты/бренды, не связанные семантически с исходной фразой). […] сначала проверь каждую формулировку на релевантность продукту, отбрось явный мусор.

Associations это семантически близкие запросы, которые Вордстат отдает вместе с частотностью основной фразы. Данные для этой статьи собраны по моему скиллу wordstat, и правило подтвердилось сразу. На фразу agent skills Вордстат предложил в близкие запросы агента 007, агента Ким и агента Смита. На anthropic skills пришли shattered pixel dungeon и скины для игр. Агент Смит к скиллам Claude отношения не имеет, хотя по-своему тоже агент и тоже мечтает подключиться ко всем системам сразу.

Обработка ошибок в файле написана так же коротко:

> Ошибка авторизации (401/403) — не повторять вслепую, явно сказать пользователю: «Wordstat API не сработал: [текст ошибки], проверь роль search-api.webSearch.user у сервисного аккаунта».

Второй пункт того же раздела про случай, когда сервис недоступен: тогда скилл берет приблизительные данные из веб-поиска и обязан прямо предупредить, что это приближение. Исключения в скилле пишутся так же, как в редполитике: что случилось и что делать дальше.

Отдельно про доступы. Чтобы ходить в Вордстат, скиллу нужны ключ и идентификатор каталога в облаке Яндекса. В файле их нет, они лежат в переменных окружения. Переменная окружения это значение, которое хранится в настройках системы на компьютере, и скилл обращается к нему по имени. Практическое следствие: сам файл можно показать кому угодно, ключ при этом останется на компьютере.

Раздел «Важно» в конце файла прямо запрещает выводить ключ в чат и в файлы. Это правило для любого скилла, который ходит во внешний сервис.

## Скилл со всеми тремя уровнями: разбор моего отчета по сайту

Второй мой скилл, weekly-site-report, в отличие от wordstat задействует все три уровня, и именно он нарисован на обложке статьи. Он собирает еженедельный отчет по этому сайту на данных Яндекс Метрики, Гугл Серч Консоли и Яндекс Вебмастера. Скилл я написал недавно и в работе еще не запускал, поэтому здесь только устройство: как я его собрал и почему так.

```
weekly-site-report/
├── SKILL.md
├── references/
│   └── thresholds.md
└── scripts/
    └── site_stats.mjs
```

### Шапка: всегда в контексте

```
---
name: weekly-site-report
description: Готовит еженедельный отчет по сайту ansudakov.ru на данных Яндекс Метрики, Гугл Серч Консоли и Яндекс Вебмастера. Использовать, когда просят отчет, сводку, статистику или «как дела у сайта» за неделю, спрашивают, что выросло и что просело в трафике или поиске.
---
```

Это первый уровень. Пока разговор не зашел про сайт, модель знает о скилле только имя и описание.

### Тело SKILL.md: открывается по совпадению

Когда задача совпадет с описанием, Claude откроет сам файл. В нем три раздела:

```
## Как собрать данные
## Что сравнить с прошлой неделей
## Формат
```

Первый говорит, чем забирать цифры. Второй перечисляет, что сравнивать: визиты и источники трафика из Метрики, показы, клики и среднюю позицию из Серч Консоли, страницы, которые сильнее всего выросли и упали, ошибки сайта из Вебмастера. Третий задает формат жестко: три коротких абзаца, сначала главное за неделю, потом цифры неделя к неделе, потом что тревожно и что с этим сделать.

### Пороги и скрипт: открываются по требованию

Третий уровень это два файла, которые модель трогает только на своем шаге. Пороги вынесены в `references/thresholds.md`, и SKILL.md отсылает к ним одной строкой: «Пороги, что считать тревожным, лежат в `references/thresholds.md`. Прочитать перед выводами». Внутри файла четыре раздела:

```
## Трафик (Метрика)
## Поиск (Серч Консоль)
## Сайт (Вебмастер)
## Что не считать тревогой
```

Главное правило стоит в самом начале:

> Блог маленький, поэтому проценты на малых числах шумят. Тревога только если выполнены оба условия: процент и абсолютное значение.

Например, визиты считаются тревожными, если упали больше чем на 20% неделя к неделе и минимум на 30 визитов. Одного процента мало: на маленьком блоге падение с 10 визитов до 7 уже дает минус 30%, и поднимать из-за него тревогу незачем. Это то же редакторское правило, что и с цифрами в тексте: процент без абсолютного числа ничего не говорит. Пороги я вынес в отдельный файл, чтобы править их, не трогая инструкцию.

Данные забирает скрипт `scripts/site_stats.mjs`, и SKILL.md прямо запрещает модели ходить в API руками: «Данные забирает скрипт, сам API руками не вызывать». Скрипт выполняется, и в контекст попадает только то, что он напечатал: цифры за две недели.

С доступами та же логика, что у wordstat: ключи скрипт берет из файлов в папке сайта, и в вывод они не попадают. Данные Серч Консоли приходят с задержкой в 2–3 дня, поэтому скрипт сравнивает недели со сдвигом, а SKILL.md требует назвать в отчете даты, за которые сравнение. Если один из сервисов не ответил, отчет собирается по остальным, с прямой пометкой, каких данных нет.

### Размер: когда пора выносить в отдельные файлы

Документация советует держать SKILL.md короче 500 строк, подробности выносить в отдельные файлы и ссылаться на них прямо из SKILL.md, без цепочек из ссылки в ссылку. У меня оба варианта: wordstat это 93 строки одной инструкцией, а у weekly-site-report SKILL.md около 40 строк, потому что пороги лежат в references, а работа с сервисами в скрипте.

## Где брать готовые скиллы и как проверить чужой перед установкой

Лучшие скиллы для Claude у каждого свои, а оценивать чужие файлы, которые я не проверял в работе, было бы нечестно. Свои два я разобрал выше. Среди встроенных у Anthropic есть еще skill-creator, помощник для написания новых, его устройство будет в разделе про то, как написать свой скилл. Остальные источники я не тестировал, поэтому даю их как адреса, без оценки:

- Репозиторий [anthropics/skills](https://github.com/anthropics/skills) на GitHub, официальные скиллы Anthropic, в том числе для Word, Excel, PowerPoint и PDF.
- Каталог внутри приложения Claude, раздел «Просмотреть навыки», там же скиллы партнеров, например Ноушна и Фигмы.
- CLI `npx skills` и его каталог skills.sh. CLI это программа, которую запускают командой в терминале. Этот проект делает Vercel Labs, сторонняя для Anthropic компания. CLI собирает анонимную статистику использования, ее можно отключить переменной окружения.

Документация Anthropic советует ставить скиллы только из доверенных источников: написанные вами или полученные от Anthropic. Чужой скилл предлагается проверять целиком и относиться к нему как к установке программы. В папке скилла могут лежать исполняемые скрипты, а скрипт на вашем компьютере способен на многое. Отдельный риск у скиллов, которые подтягивают данные по внешним ссылкам: содержимое по ссылке может поменяться уже после того, как вы скилл проверили.

### Что проверить в чужом скилле перед установкой

1. Прочитать SKILL.md целиком, включая описание. Совпадает ли то, что заявлено в шапке, с тем, что написано в теле.
2. Открыть папку `scripts/`, если она есть, и понять, что делает каждый файл. Программистом для этого быть не обязательно: название и первые строки скрипта обычно говорят достаточно, а непонятный файл можно показать тому же Claude и спросить.
3. Проверить, не ходит ли скилл в интернет и не тянет ли данные по ссылкам.
4. Понять, что именно скилл меняет в поведении модели и нужно ли это вам.

Ко второму пункту есть ориентир на собственном файле. Первые четыре строки моего `site_stats.mjs` это комментарий: что скрипт собирает, как его запускать, откуда он берет доступы и что ключи в вывод не попадают. У аккуратно сделанного чужого скрипта такое объяснение обычно тоже есть. Если его нет, это уже повод присмотреться внимательнее.

Чек-лист ловит не все. Документация сама приравнивает чужой скилл к установке программы, и это хорошая мерка: если вы не поставили бы программу от этого автора, его скилл тоже лучше не ставить.

## Как установить скилл в Claude и Claude Code

Скилл это папка с файлом SKILL.md, и ставится она по-разному в зависимости от того, где вы работаете с Claude. Скиллы работают в приложении и на сайте Claude, в Claude Code, через API, в Cowork и в надстройках Microsoft 365. Подробно разберу первые два.

Оговорка для читателей из России: официально Claude здесь недоступен, нужна зарубежная карта или посредник. Инструкции по обходу в этой статье нет. Про тарифы и доступ я подробнее писал в [сравнении нейросетей для редактирования текста](/blog/kak-redaktirovat-teksty-neiroseti).

### В приложении Claude

Готовые скиллы Anthropic для Word, Excel, PowerPoint и PDF ставить не нужно. Они срабатывают сами, когда вы просите сделать документ.

Свой или чужой скилл загружается zip-архивом. Путь по русской справке: «Настроить» → «Навыки», затем плюс и загрузка навыка. В английском интерфейсе это Customize > Skills и Upload a skill. Для работы скиллов должна быть включена функция выполнения кода и создания файлов, она находится в настройках, в разделе возможностей. Корнем архива должна быть папка скилла, и ее имя совпадает с полем name в шапке.

Тем же плюсом скилл можно создать прямо в интерфейсе, пункт Create skill.

С тарифами источники Anthropic расходятся. Готовые скиллы, судя по справке, работают и на бесплатном тарифе, свои точно доступны на платных. Про свои скиллы на бесплатном тарифе справка и документация пишут разное, так что надежнее проверить у себя в настройках.

Свои скиллы в приложении личные, у каждого пользователя свои. На тарифах Team и Enterprise их можно публиковать для коллег.

Подводный камень: приложение принимает в шапке только поля стандарта. Если скилл писался для Claude Code с его дополнительными полями, при загрузке он получит ошибку про лишние ключи вида `Unexpected key(s) in SKILL.md frontmatter`. Чтобы ее избежать, хватит имени и описания.

### В Claude Code

Claude Code работает с файлами на вашем компьютере. Я пользуюсь им во вкладке Code десктопного приложения Claude.

Свой скилл здесь это просто папка на диске, загружать ее никуда не нужно. Положите ее в `~/.claude/skills/`, и скилл будет доступен во всех проектах. Положите в `.claude/skills/` внутри папки проекта, и он будет работать только там. Тильда в начале пути означает домашнюю папку пользователя.

Вызвать скилл можно командой `/имя`, например `/wordstat`. Или ничего не делать: Claude выберет его сам по описанию, как в моем случае с Вордстатом. Старые слэш-команды из `.claude/commands/` слиты со скиллами и продолжают работать.

Чужой скилл с GitHub можно поставить через CLI `npx skills`, команда в общем виде такая:

```
npx skills add автор/репозиторий
```

Команда `npx` входит в Node.js, среду для запуска программ на JavaScript, поэтому Node.js должен стоять на компьютере заранее. Если его нет, терминал ответит, что команда не найдена.

По умолчанию CLI кладет файлы в общую папку `~/.agents/skills`, а в папку скиллов Claude Code ставит на нее ссылку, симлинк. Симлинк работает как ярлык: папка одна, но видна в двух местах, и правка в ней сразу видна везде. Если терминал пугает, есть ручной путь: скачать папку скилла и скопировать ее в `~/.claude/skills/`.

Готовые скиллы Anthropic для документов в Claude Code по умолчанию не входят. Их можно поставить из репозитория anthropics/skills как плагин, начинается все с команды `/plugin marketplace add anthropics/skills`. Что такое плагин, объясню ниже, в разделе про соседние инструменты.

### Синхронизация из приложения в Claude Code

Скиллы, включенные в аккаунте claude.ai, Claude Code сам скачивает в папку `~/.claude/skills/synced/`. Синхронизация идет в одну сторону: если поправить файл в этой папке, правка затрется при следующем обновлении.

Раз Claude Code у меня открыт внутри десктопного приложения, я вижу оба мира сразу. В папке synced у меня лежат скиллы Anthropic для документов и skill-creator, пришедшие из аккаунта.

И про интернет. В Claude Code у скилла есть доступ в сеть, как у любой программы на компьютере. Через API у скиллов сети нет совсем, в приложении доступ зависит от настроек. Поэтому скилл, который ходит во внешний сервис, как оба моих, прежде всего сценарий для Claude Code.

## Описание скилла пишется как заголовок

Описание единственное, по чему Claude решает, открывать ли скилл. Оно должно сказать две вещи: что скилл делает и когда его применять. Если описания размыты или похожи друг на друга, модель откроет не тот файл или пропустит нужный.

В Claude Code описания к тому же обрезаются. Весь список описаний получает бюджет около 1% контекстного окна. Когда список не помещается, первыми режутся описания скиллов, которые вы вызываете реже всего. Каждая запись при этом ограничена 1536 символами. Документация советует прямым текстом: put the key use case first, то есть главный сценарий ставить в начало.

Редактору эта задача знакома по заголовкам в выдаче: их тоже обрезают на середине, и по ним человек решает, кликать ли. Здесь решает модель.

**wordstat.** Шапка показана выше. В ней есть обе половины: что скилл делает (частотность, поисковый интент, близкие запросы через Вордстат) и когда он нужен (пользователь просит проверить или собрать ключи, частотность, семантику). В ней стоят слова, которыми задачу ставит живой человек: частотность, ключи, семантика. По смыслу с ними и совпал мой запрос из начала статьи.

Есть уточнение против сужения: не только для лендингов. Без такой оговорки описание легко прочитать как скилл для одного вида работы.

И есть форма: безличный инфинитив «Использовать при». Документация советует писать описание в третьем лице, без «я помогу» и «вы можете». Безличная форма работает так же.

**weekly-site-report.** Шапка тоже показана выше. Первая фраза говорит, что скилл делает и на чьих данных: еженедельный отчет по конкретному сайту из трех сервисов, сайт назван прямо. Вторая фраза перечисляет слова, которыми я спрашиваю про сайт: отчет, сводка, статистика, а еще разговорное «как дела у сайта» и «что выросло и что просело». Модели не нужно угадывать, что вопрос про просевший трафик тоже повод открыть этот файл. Форма здесь другая: третье лицо, «Готовит», ровно как советует документация.

**docx от Anthropic.** Самое длинное описание из трех, около 900 знаков, и самое показательное. Сначала подробно перечислено, когда включаться: любое упоминание Word, файлов .docx, правка документов с примечаниями. В конце сказано, когда скилл не нужен: Do NOT use for PDFs, spreadsheets, Google Docs… Так описание разводит соседние скиллы между собой, как редактор разводит похожие рубрики, чтобы автор не гадал, куда нести текст. Похожая строка есть у скилла google-workspace: Word, Excel, PowerPoint и PDF он отдает соседям.

Из трех шапок складываются правила:

- Описание говорит, что скилл делает и когда его применять.
- В нем слова, которыми вы сами ставите задачу в чате.
- Главное стоит в первых строках.
- Форма третьего лица или безличная.
- Если рядом есть похожий скилл, прямо написано, когда этот не нужен.

Проверить описание можно без всякого программирования. Поставьте Claude задачу несколькими разными формулировками, ни разу не называя скилл, и посмотрите, откроется ли он. Если скилл молчит, править нужно описание.

В skill-creator это вынесено в отдельный шаг, и в его инструкции так и написано: run the skill description improver, which we have a whole separate script for, to optimize the triggering of the skill. Под улучшение одного абзаца у Anthropic заведен отдельный скрипт. Редактор, который годами переписывает заголовки, такую заботу о формулировке оценит.

<div className="callout">Описание скилла читает модель и по нему одному решает, открывать ли файл. Пишите его как заголовок, который обрежут.</div>

## Как написать свой скилл: от чек-листа к рабочей папке

Начать проще всего с документа, который уже есть. В документации Claude Code есть таблица о том, как наращивать настройку со временем, и в ней точная примета: если один и тот же регламент или многошаговую процедуру вы вставляете в чат третий раз, пора упаковать ее в скилл. У редактора такой документ почти всегда под рукой. Чек-лист вычитки, стоп-лист, порядок проверки фактов: то, что каждый раз копируешь в чат заново.

Свой скилл ценнее готового по простой причине: он написан под ваши тексты, ваш процесс и ваши правила. Чужой собран под задачи своего автора, даже если он хороший.

Порядок действий:

1. Выберите одну процедуру. Одна задача, один скилл: вычитка по стоп-листу и сбор семантики живут в разных папках.
2. Создайте папку. Имя латиницей, строчными буквами, слова через дефис, например `press-release-check`. Это же имя пойдет в поле name.
3. Создайте в папке файл SKILL.md и напишите шапку: name и description по правилам из раздела выше.
4. Напишите тело как регламент: когда применять, порядок шагов, исключения, запреты, как выглядит результат. Пример готового результата внутри файла помогает модели больше, чем его описание словами.
5. Положите папку туда, где ее найдет Claude Code, или упакуйте в zip для приложения. Сжимайте саму папку скилла, чтобы в архиве она лежала первой.
6. Проверьте срабатывание, не называя скилл, и при необходимости поправьте описание.

Ниже шаблон, с которого можно начать. Это заготовка с пустыми местами под ваш регламент:

```
---
name: my-skill
description: Что делает скилл, одной фразой. Использовать, когда пользователь просит (перечислить слова, которыми вы сами ставите задачу).
---

# Название скилла

## Когда применять
Ситуации и слова в запросе, при которых скилл нужен.

## Порядок
1. Первый шаг.
2. Второй шаг.
3. Как выглядит готовый результат, лучше с примером.

## Чего не делать
- Запреты и исключения.
```

Файл можно и вовсе не писать руками. В приложении скилл создается прямо в интерфейсе, пунктом Create skill, о котором шла речь в разделе про установку. Можно вставить свой регламент в обычный диалог и попросить Claude собрать из него скилл. И можно воспользоваться встроенным skill-creator.

Судя по его инструкции, skill-creator работает как редактор с автором. Выясняет, что скилл должен делать и когда срабатывать, пишет черновик, прогоняет тестовые запросы, оценивает результат и переписывает. Отдельным шагом улучшает описание под срабатывание. Еще в его инструкции есть строка о том, кто вообще будет им пользоваться: Claude, по наблюдению Anthropic, вдохновляет сантехников открывать терминал, а родителей, бабушек и дедушек гуглить, как установить npm. Редакторов в этом списке пока нет, хотя по уровню страха перед терминалом мы где-то между сантехниками и дедушками.

### Ошибки в шапке, из-за которых скилл не загружается

- Файл начинается не с трех дефисов. Шапка должна стоять в самой первой строке: пустая строка или любой текст перед ней, и шапку уже не найдут. Отсюда ошибка вида SKILL.md must start with YAML frontmatter, которую ищут дословно.
- Двоеточие с пробелом внутри описания. Для шапки это знак нового поля, и она перестает читаться. Если без двоеточия не обойтись, возьмите описание целиком в кавычки.
- Неправильное имя: заглавные буквы, пробелы, слова claude или anthropic, несовпадение с названием папки. Имя до 64 символов, только строчные латинские буквы, цифры и дефис.
- Лишние поля при загрузке в приложение. Шапка из name и description переносится лучше всего. Стандарт допускает и другие поля, например `compatibility` и `allowed-tools`, но в моих скиллах их нет: двух полей хватает.

Про допустимую длину описания источники Anthropic расходятся: в справке и в документации цифры разные. Поэтому безопасный совет один: самое важное в первой строке.

## Скиллы для редактора и маркетолога: образцы, которые можно взять за основу

У меня есть заготовка, которая превращает голосовую заметку в пост для телеграм-канала в моем голосе. Наговариваю мысль, получаю пост своими словами. С такой задачи удобно начать любому маркетологу или эксперту: наговорить мысль проще, чем сесть и написать.

Для SEO и отчетов по сайту у меня есть wordstat и weekly-site-report. Ниже три образца для других задач. Шапка в каждом написана по правилам из раздела про описание, тело сокращено до каркаса.

**Образец**

```
---
name: redpolitika-check
description: Проверяет черновик статьи по редполитике блога, включая стоп-лист, тире, кавычки, букву ё и длину абзацев. Использовать, когда просят вычитать, проверить или отредактировать текст для блога.
---

## Порядок
1. Прочитать REDPOLITIKA.md целиком.
2. Пройти черновик по стоп-листу, каждое совпадение выписать с цитатой.
3. Отметить тире, декоративные кавычки и ё вне минимальных пар.
4. Отметить абзацы длиннее пяти предложений.
5. Спорные места вынести отдельным списком, решение оставить автору.
```

Упакованная в скилл, редполитика срабатывает в любом разговоре, где я прошу вычитать текст, и ее не нужно каждый раз прикладывать к запросу.

**Образец**

```
---
name: brief-from-call
description: Собирает бриф по расшифровке созвона с клиентом. Использовать, когда присылают расшифровку, запись или заметки со встречи и просят бриф, задание или итоги договоренностей.
---

## Шаблон
- Задача
- Аудитория
- Ограничения
- Открытые вопросы

## Правила
- Формулировки клиента сохранять дословно.
- Все, что на созвоне не прозвучало, выносить в открытые вопросы.
```

После созвона в расшифровке обычно есть все нужное, только вперемешку. Скилл каждый раз раскладывает это по одному шаблону.

**Образец**

```
---
name: press-release-check
description: Проверяет пресс-релиз перед рассылкой по чек-листу. Использовать, когда просят вычитать, проверить или доработать пресс-релиз или новость для СМИ.
---

## Чек-лист
1. Новость стоит в первом абзаце.
2. Есть цифры и проверяемые факты.
3. Цитата спикера звучит как речь живого человека.
4. Есть контакт для прессы с именем.
5. Журналист поймет суть без звонка в компанию.
```

Логику текстов от лица компании, от постов до пресс-релизов, я разбирал в [основах PR для редактора](/blog/osnovy-pr-dlya-redaktora). Чек-лист выше удобно держать скиллом: пресс-релизы пишутся нечасто, и пункты успевают забыться.

## Скилл, CLAUDE.md, агент, MCP или плагин: что выбрать под задачу

Когда хватает инструкции проекта, а когда документ пора упаковать в скилл? Инструкция проекта в приложении и CLAUDE.md в Claude Code (файл с правилами, который лежит в папке проекта) находятся в контексте всегда и целиком. Они подходят для правил, которые действуют в каждом разговоре. Скилл подгружается, когда задача совпала с описанием, и подходит для процедур, которые нужны время от времени. Документация советует держать CLAUDE.md короче 200 строк, а многошаговые процедуры выносить в скиллы.

В статье про [тон-оф-войс и то, как применять его в ежедневной работе](/blog/ton-of-vois-dokument-kotorym-polzuyutsya), я советовал загружать документ в нейросеть как инструкцию проекта. Скилл это следующий шаг: правила голоса остаются в инструкции, а процедура проверки по ним переезжает в скилл и включается, когда нужна.

| Инструмент | Как работает | Когда выбирать |
|---|---|---|
| Инструкция проекта, CLAUDE.md | В контексте всегда, целиком | Правила на каждый разговор |
| Скилл | Описание всегда, остальное по совпадению | Процедура, чек-лист, регламент под задачу |
| Агент (субагент) | Свой исполнитель со своим контекстом | Работа в стороне, свежим взглядом |
| MCP (в приложении коннекторы) | Подключение к внешнему сервису | Нужны данные или действия в другой программе |
| Плагин | Пакет для Claude Code | Поставить скиллы, агентов, MCP и хуки разом |
| Хук | Скрипт на событие | Действие, которое должно случиться гарантированно |

Агент делает работу в стороне, со своей инструкцией и чистым контекстом, и возвращает итог. Слэш-команда в Claude Code теперь просто способ вызвать скилл вручную, по имени. Custom instructions в настройках профиля действуют на все разговоры сразу, скилл привязан к задаче.

Разницу между MCP и скиллом проще всего показать на вопросе, который я задал себе сам. У меня к сайту подключены Яндекс Метрика, Гугл Аналитикс, Гугл Серч Консоль и Яндекс Вебмастер, статистику можно спросить в любой момент. Есть и скрипты для SEO-аудита и проверки скорости страниц. В какой-то момент я спросил себя: это уже скилл?

Подключение дает модели доступ, это ее руки: API, скрипты, коннектор. Скилл это процедура поверх доступа: как читать данные и что с ними делать.

Ответ на свой вопрос я в итоге записал скиллом weekly-site-report. Доступы к сервисам и скрипт там это руки. SKILL.md и пороги это процедура: что сравнить, что считать тревожным, в каком виде отдать. В справке Anthropic это сформулировано коротко: скиллы учат процедуре, MCP подключает к сервисам.

Все слои сразу работают в конвейере, который помогает мне готовить статьи для этого блога. Пишу их я сам. Конвейер берет на себя подготовку и проверки, а финальное слово по каждому тексту всегда за мной. Из чего он состоит:

1. CLAUDE.md с правилами конвейера, Claude читает его в каждой сессии.
2. 14 агентов: семь помогают на этапах (тема, бриф, SEO, структура, черновик, иллюстрация, сборка превью), семь проверяют их работу свежим взглядом, и проверяющий не видит хода мысли того, кто работу делал.
3. Скилл wordstat, он работает в основном диалоге.
4. Редполитика отдельным файлом, который агенты читают как источник правды.

Как устроен агент-редактор, который сверяет черновик с документом по пунктам, я описывал в той же [статье про тон-оф-войс](/blog/ton-of-vois-dokument-kotorym-polzuyutsya).

Одна деталь моей настройки. По документации агент может пользоваться скиллами сам. В моем конвейере агенты команды не запускают, поэтому данные из Вордстата собираются по моему скиллу в основной сессии, и агент получает готовые цифры.

И последнее про границы. Запрет в скилле модель читает и обычно выполняет. Гарантию на уровне программы дают хуки: они срабатывают на событие независимо от того, что решит модель.

## Работают ли скиллы в Codex и других программах

Формат Agent Skills Anthropic выпустила как открытый стандарт, с конца 2025 года спецификация лежит на [agentskills.io](https://agentskills.io/specification). В списке программ, которые его поддерживают, есть Codex и ChatGPT, Cursor, GitHub Copilot, VS Code, Gemini CLI и другие.

Стандарт описывает ровно то, что разобрано в этой статье: папку с файлом SKILL.md, шапку с именем и описанием и необязательные папки для скриптов, справки и шаблонов. Поэтому CLI `npx skills` из раздела про установку предлагает выбрать, для каких программ поставить скилл, а файл при этом один и лежит в общей папке `~/.agents/skills`. Сам я пользуюсь Claude Code и Codex.

Для переносимости держите шапку из name и description. Поля, которые знает только Claude Code, в другой программе могут не прочитаться или сломать загрузку. Какие из программ со скиллами доступны из России, я не проверял.

## Частые вопросы

### Скиллы и навыки в Claude это одно и то же?

Да. Навыки это название функции в русской справке Anthropic, в английской она называется Skills.

### Как правильно: скил или скилл?

Я пишу с двумя «л»: двойное ll в английских заимствованиях обычно сохраняется, как в словах холл и тролль. Ищут обоими способами, речь об одном и том же. Английское skill и навык из русской справки тоже про него.

### Что значит ошибка SKILL.md must start with YAML frontmatter?

Файл должен начинаться с трех дефисов в самой первой строке. Проверьте, нет ли перед шапкой пустой строки или текста и нет ли в описании двоеточия с пробелом. Подробнее в разделе про ошибки в шапке.

### Чем SKILL.md отличается от CLAUDE.md и AGENTS.md?

CLAUDE.md хранит правила проекта, Claude Code читает его в каждой сессии целиком. SKILL.md это инструкция под конкретную задачу, она открывается, когда задача совпала с описанием. AGENTS.md это отдельный файл с инструкциями для агентов. Со скиллами он не связан.

### Где скачать скиллы для Клода?

Официальные лежат в репозитории anthropics/skills на GitHub, часть доступна прямо в каталоге приложения Claude, сторонние собраны в каталоге skills.sh. Перед установкой любого чужого скилла пройдитесь по чек-листу из раздела про то, где брать готовые.

Скилл передает модели не чутье редактора, а его регламент: чек-лист, стоп-лист, порядок шагов. История бренда, разговор с клиентом и ощущение, как фраза сядет у аудитории, остаются у человека. Этот разрыв я разбирал в статье о том, [почему улучшение промпта не закрывает разрыв в контексте](/blog/kak-redaktirovat-teksty-neiroseti), и к скиллам он относится в той же мере. Скилл забирает другую часть работы: объяснять модели одни и те же правила в каждом новом разговоре.

Следующий шаг простой. Найдите документ, который вы вставляете в чат третий раз, и сделайте из него первый скилл. Начните с описания: две фразы о том, что он делает и когда нужен. Если Claude откроет скилл сам, без имени, значит, заголовок получился.
